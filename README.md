# 代理时区助手

按桌面版 Chrome 125 及以上版本的原生 API 开发。已在 Edge 155 的独立测试配置完成实际检查，Chrome 请按下面方式加载后验证。本工具是本地浏览器扩展，不能粘贴进 Tampermonkey。

按出口 IP 查询 IANA 时区，再调用 Chrome 的原生时区设置。它会让已启用标签中的常见 Date 和 Intl 接口使用这个时区。电脑时区不变，UTC 时间戳也不应改变。

## 安装

1. 解压安装包。
2. 在 Chrome 地址栏输入 `chrome://extensions`，打开开发者模式。
3. 点击“加载已解压的扩展程序”，选择含 `manifest.json` 的 `proxy-timezone-extension` 文件夹。
4. 将“代理时区助手”固定到工具栏。

## 使用

1. 打开代理，然后打开需要使用的网站。
2. 点击工具栏中的“代理时区助手”，在“启动方式”中选择手动、指定网站或所有网站。指定网站模式需要填写规则，或点击“添加当前网站”。
3. 手动模式或临时处理时，点击“查询出口并应用”。查看查询到的 IP、城市和时区是否符合当前代理。
4. 保存正在输入的内容后刷新网页。也可以先勾选刷新选项，再点击应用。
5. 点击“验证当前页”，核对页面实测时区。

美国西部节点常见的时区是 `America/Los_Angeles`。冬季通常为 UTC-8，夏季通常为 UTC-7。工具使用查询结果，不固定写成 UTC-8。

## 启动方式

弹窗顶部可以选择三种方式：

- **手动**：保持原来的行为，只有点击“查询出口并应用”才处理当前标签。
- **指定网站**（推荐）：访问匹配规则的网站时自动启用；离开时默认恢复。规则每行一条，支持 `chatgpt.com`、`*.openai.com`、`https://claude.ai/chat/*`。`example.com` 只匹配该主机，`*.example.com` 同时匹配主域和子域。
- **所有网站**：每个普通 http/https 网页都自动启用。调试提示会出现在每个标签上，通常不建议默认使用。

自动模式会先查询出口时区。若出口时区与电脑本机时区相同，默认不启用；可以在弹窗中关闭这个跳过选项。出口查询结果缓存 10 分钟，避免每次导航都请求 `ipwho.is`。

## 自动启动的工作方式

自动模式监听标签导航，而不是轮询网页：

1. 导航开始时匹配站点规则，尽早连接调试器并设置时区。
2. 导航提交后校验页面实际时区；如果页面在设置前已经执行了首屏脚本，自动刷新一次。刷新有 60 秒防循环，且可以在弹窗中关闭。
3. 离开匹配站点时清除时区并断开调试器（可在弹窗中关闭“离开站点后恢复”）。
4. 所有已启用标签仍然共用一个时区；同一站点的多个标签不保证能使用不同时区。

自动刷新会丢失未保存的编辑内容。默认只对首次进入或导航后的页面刷新，不会对站内 SPA 路由变化反复刷新。

开启“每 5 分钟检查出口”后，工具只在存在已启用标签时查询。时区变化后，它会更新这些标签，但不会自动刷新。网页先前保存的时区可能仍需刷新才能更新。浏览器休眠会推迟检查，切换节点后可立即点击“查询出口并应用”。自动查询失败时会保留先前设置，并显示错误。点击查询并应用失败时不会悄悄使用上次查询结果。

“只查询出口”不会改变时区。手动设置位于展开区域，使用 `America/Los_Angeles` 或 `Asia/Singapore` 这样的城市名称。

## 恢复

点击“恢复当前页”，然后刷新。关闭已启用的标签也可以结束该标签的设置。关闭或移除扩展可停止使用。电脑时区始终不变。自动模式下，恢复后再次进入匹配站点仍会自动启用；需要彻底停用请切换到手动模式。

Chrome 可能在顶部显示这个扩展正在调试浏览器，这是原生时区功能需要的提示。打开该标签的开发者工具或取消调试提示可能使设置断开。此时工具显示 OFF；自动模式下，下次导航可能重新连接，手动模式下需要再次应用。工具不会自动抢占其他调试程序。

## 代理分流与使用范围

出口查询使用 `https://ipwho.is/`。请让这个域名和目标网站走同一条代理规则。例如 ChatGPT 经过美国节点，但查询服务直连时，查询结果就不能代表 ChatGPT 的出口。扩展无法从 IP 查询证明不同域名的路由相同。IP 地理数据库也可能不准确，可以手动改正。

时区不同不能单独证明网页加载异常的原因。若应用后 ChatGPT 仍无法加载，应检查代理连接、相关域名和 WebSocket。这个工具不会改变账号权限、服务可用地区或服务器端的网络判断。

扩展会处理主页面，并尝试处理跨进程 iframe 与 Dedicated Worker。Shared Worker、已有 Service Worker、浏览器内部页面和其他独立运行环境不保证覆盖。验证按钮只检测主页面，不代表整个网站的所有执行环境都通过。部分子内容处理失败会显示提示，并尽力恢复执行。

Chromium 的时区设置可能由同一渲染进程中的页面共享。不要让多个时区工具同时工作。本工具使用一个统一时区，不能保证同一站点的多个标签可以各自使用不同的时区。恢复某个标签后，其他共享进程的标签也建议重新验证。

## 权限与数据

- `debugger` 用于设置原生时区并读取页面的 Date 和 Intl 检测结果。该权限本身范围较广，安装前可以检查本目录源码。
- `tabs` 与 `webNavigation` 用于在导航时判断当前网站是否匹配规则，以及读取标签地址。扩展不会保存浏览历史。
- `storage` 在本机保存选定时区、启动方式、站点规则、最近一次查询结果和错误。已启用标签记录仅保存到当前浏览器会话。
- `alarms` 用于可选的定期检查。
- `activeTab` 用于选择当前标签。
- 唯一的外部查询域名是 `ipwho.is`。查询服务会看到该次请求的出口 IP。代码不会发送网页内容、聊天、Cookie 或账号数据。没有远程脚本依赖。

## 开发验证

使用 Node.js 24 或以上版本，在项目根目录运行 `npm test` 检查查询、输入、站点规则、自动启用决策和多标签恢复处理。运行 `npm run test:browser` 进行独立浏览器检查。测试使用单独的临时 profile，不使用日常浏览器配置。

具体执行结果见 [验证记录](proxy-timezone-extension/VALIDATION.md)。未记录通过的项目，不应当作已验证。
